# PC 카카오톡 조작 설명서 (Windows 26.9.2.5342, 영어 UI, 배율 200%)

작성 2026-11-16. 봇(`bot.py` → `iris_native.py` → `pc_kakao_send.py`, `pc_kakao_thread.py`)이 쓰는 창·버튼·메뉴와 조작 방법을 실제로 재서 적었다.
"실측"이라고 쓴 것만 직접 확인했다. "미확인"은 눌러 보지 않았거나 못 연 것이다.

좌표는 **창 왼쪽 위 기준 물리 픽셀(DPI 192)** 이다. 다른 배율에서는 `GetDpiForWindow(hwnd) / 192` 를 곱한다. 창 크기를 바꾸면 오른쪽·아래쪽 기준 값(전송 버튼 등)만 믿는다.

## 0. 원칙

| 할 일 | 방법 | 쓰지 않는 것 |
|---|---|---|
| 메시지 읽기 | 복호화한 로컬 DB. `POST http://127.0.0.1:3001/query` `{"query": "SELECT … FROM chat_logs …", "bind": []}` | 채팅창 캡처·글자 인식 |
| 메시지가 화면 어디 있는지 | 그 점을 우클릭 → 메뉴의 Copy → 클립보드 글을 DB 글과 비교 | 그림 인식 |
| 누르기·입력 | `PostMessage` 창 메시지(마우스·포커스 안 움직임) | SendInput, 화면 좌표 클릭(computer use) |
| 버튼·메뉴 배치 알아내기 | `PrintWindow` 로 그 창만 그림으로 떠서 한 번 본다 | — |

`chat_logs` 열: `_id`(메시지 id), `chat_id`, `user_id`, `type`(1 글, 2 사진, 20 이모티콘, 26 답장, 0 알림), `message`, `created_at`, `thread_id`, `scope`(1 본문, 2 스레드 댓글, 3 함께 보내기 댓글).

## 1. 반드시 지킬 것 (실측한 사고에서 나온 규칙)

1. **메뉴(`EVA_Menu`)가 떠 있는 동안 채팅창·목록에 클릭 메시지를 넣지 않는다.** 그 클릭이 메뉴 항목으로 들어간다. 2026-11-16 조사 중 늦게 뜬 메뉴가 남은 채로 다음 우클릭을 넣어 'Announce' 확인창이 12개 떴다(OK를 누르지 않아 공지는 안 바뀜, 전부 닫음).
   - 클릭 전에 보이는 `EVA_Menu` 가 0개인지 확인하고, 있으면 `WM_CLOSE` 로 닫는다(실측: 바로 닫힘. Esc 키 메시지도 닫힘).
   - 메뉴는 최대 1초 기다리고, 안 떠도 0.25초 뒤 한 번 더 확인해 늦게 뜬 것을 닫는다.
2. **확인창에는 Enter·OK를 절대 보내지 않는다.** 뜻밖의 창은 `WM_CLOSE`(= 취소)로 닫고 작업을 실패로 끝낸다.
3. **메뉴 높이가 같아도 항목이 다를 수 있다.** 오픈채팅 남의 글 메뉴와 나와의 채팅 내 글 메뉴는 둘 다 564px인데 첫 항목이 각각 'Reply in thread', 'Reply'다. 방 종류를 DB(`chat_rooms.type`)로 먼저 확인한다.
4. **닫힌 방 열기의 검색 대기(`search_settle`)는 0.4초 아래로 줄이지 않는다.** 0.2초로 줄였더니 검색 결과가 뜨기 전에 Enter가 들어가 방이 안 열렸다.
5. 실험은 메뉴 열기·모드 전환까지만 한다. 실제 전송은 시험하지 않는다(나와의 채팅 포함). 끝나면 답글 모드·검색칸 글·클립보드를 되돌리고 창 트리로 확인한다.
6. 클립보드를 쓰는 동작(위치 찾기)은 글은 되돌리지만 그림 등 글이 아닌 내용은 못 되돌린다.

## 5. 조작 방법

### 5-1. 닫힌 방 열기 (실측)
메인 창 검색칸 `Edit`에 `WM_SETTEXT`(방 이름) → 0.4초 → `Enter` 키 메시지 → 0.5~1초 뒤 방 창이 뜬다 → 검색칸 비우기. 메인 창이 최소화·숨김이어도 된다. `PK.open_chat(방 이름, execute=True)`. 방을 열면 안 읽은 글이 읽음 처리된다.

### 5-2. 보내기 (실측, 봇이 쓰는 길)
입력칸에 `EM_SETSEL`(전체) + `EM_REPLACESEL`(글) → `WM_GETTEXT`로 확인 → 입력칸에 `Enter` 키 메시지 → 입력칸이 비워지면 성공. 0.6초 안에 안 비면 Send 버튼 자리에 클릭 메시지(최대 3번).
- `WM_SETTEXT`로 넣으면 Send가 회색으로 남아 안 나간다.
- 클릭 메시지는 `SetThreadDpiAwarenessContext(-4)` 안에서 넣는다. 밖에서 넣으면 좌표가 배율만큼 커져 창 밖을 누른다.
- 빈 입력칸을 읽으면 안내문 `Enter a message`(답글 모드 `Enter a reply`)가 나온다. 초안으로 보지 않는다.
- 진짜 전달 확인은 DB에 내 글이 들어왔는지로 한다.

### 5-3. 목록을 맨 아래로 (실측)
목록 컨트롤에 `WM_VSCROLL`(0x0115), wParam 7(SB_BOTTOM). End 키 메시지, 마우스 휠 메시지도 된다. 창이 뒤에 있으면 새 글이 와도 목록이 따라 내려가지 않으므로 위치를 찾기 전에 항상 한다.

### 5-4. 화면을 읽지 않고 메시지 위치 찾기 (실측)
1. DB에서 대상 글과 `_id`를 읽는다.
2. 목록을 맨 아래로 내린다.
3. 아래에서 위로 44px씩 올라가며 (x=200, y) 우클릭 → 메뉴 높이가 564면 Copy(y=353) 클릭 → 클립보드 글이 대상 글과 같으면 그 y가 그 말풍선이다.
4. 클립보드 글은 시작 전에 저장했다가 되돌린다.
- 가장 새 글이면 1번에 찾고 0.8초, 8번째 시도면 2.7초 걸렸다.

### 5-5. 스레드(댓글) 답장 (모드 전환까지 실측, 실제 전송은 미확인)
1. 5-4로 대상 말풍선의 y를 찾는다.
2. 같은 점을 우클릭 → 메뉴 첫 항목 Reply in thread(y=30) 클릭.
3. 답글 모드 확인: 입력칸 x가 27→67, 목록 높이가 106 줄고, 입력칸 위에 'Reply to <이름>' 배너와 X가 생긴다. 배너는 움직이며 나타나므로 크기가 0.15초 동안 그대로일 때까지 기다린다.
4. 다시 확인: 같은 글을 아래에서부터 한 번 더 찾아 복사해 본다. DB의 그 방 마지막 `_id`가 시작 때와 다르면(새 글이 와서 밀림) 취소한다.
5. 5-2로 보낸다. 답글 배너에 '채팅방에도 보내기' 체크박스는 없다.
6. 보낸 뒤 답글 모드가 남아 있으면 X(707, 993)로 끈다.
- 대상 글이 화면 밖이면 방 안 검색으로 이동한다(실측, 5.7초): 돋보기(창 오른쪽에서 222px, y 115) 클릭 → 검색칸 `Edit`에 `AttachThreadInput` + `SetFocus`로 입력 포커스를 준다 → 글 첫 줄 30자를 `WM_CHAR`로 넣는다 → `Enter` → 2초쯤 뒤 목록이 그 글로 옮겨진다. 포커스 없이 Enter만 보내면 검색이 실행되지 않는다. 이모지(U+FFFF 초과)는 `WM_CHAR`로 깨지므로 그 앞까지만 넣는다. 창은 앞으로 나오지 않지만 카톡 안의 입력 포커스는 검색칸으로 옮겨진다. 끝나면 검색 줄 X(창 오른쪽에서 47px, y 220)로 닫는다.
- 검색 줄이 열렸는지는 목록의 위쪽 y가 검색칸 아래쪽보다 큰지로 본다(검색칸 `Edit`는 닫힌 뒤에도 크기가 남는다).
- 코드: `pc_kakao_thread.enter(chat_hwnd, 대상 글, guard)`, `cancel(chat_hwnd)`, `in_reply_mode(chat_hwnd)`. 전송 경로는 `PK.send(..., thread_id=, thread_text=, thread_guard=)`, 셔임 `/reply` 의 `threadId`.
- 대상 글을 못 찾거나 확인이 어긋나면 **보내지 않는다**(본문으로 새지 않게).
- 스레드는 오픈채팅 기능이다. 갠톡·일반 단톡에서 같은 자리는 'Reply'(인용 답장)다.

## 8. 봇 설정과 연결

- 응답 속도 값은 `config.json`: `native_poll_sec`, `dm_debounce_sec`, `reply_delay_sec`, `room_cooldown_sec`, `part_gap_sec`. 바로 답하게 하려면 0.5 / 2 / [0, 0.3] / 2 / [0.3, 0.7].
- 방별 고정 안내는 `config.json` 의 `room_faq`: `all`(전부 걸려야 함)·`none`(하나라도 걸리면 제외) 낱말 규칙 → `confirm`(모델에게 한 번 더 확인) → 같은 사람 24시간·방 30분에 한 번 → `thread: true` 면 그 글의 스레드로. 끄려면 `enabled: false`.
- 설정은 봇 시작 때만 읽는다.

## 9. 아직 재지 않은 것

- 스레드 답글 모드에서 실제 전송과 DB `thread_id` 확인.
- 메인 창의 모든 메뉴, 설정 창.
- 일반 단톡·갠톡의 남의 글 메뉴, 사진·이모티콘·파일 메뉴 항목.
- + 메뉴의 Capture 하위 항목, Send 옆 ∨(글이 있을 때), 파일 버튼, 투명도 막대.
- 한국어 UI에서의 메뉴 높이(영어 UI와 같을 것으로 보지만 재지 않음).
